# NewsClaw

**AI 行业动态，不只是搜到，更要核验、生产、交付并留下运营反馈。**

NewsClaw 是一个面向全球与中国 AI 圈的垂类内容运营系统。它跟踪模型发布、
具身智能和机器人、芯片与基础设施、大厂 AI 产品、开源、融资合作和政策动态，
把一次“今天有哪些值得关注的 AI 事件”变成可审计的业务闭环。

```text
发现 -> 证据核验 -> 选题确认 -> 多 Agent 生产
-> 合规/人工审批 -> 飞书通知/小红书素材 -> 记忆与 Skill 反馈
```

## 为什么不是一个通用新闻助手

时间敏感的行业内容有三类常见失败：

- 搜索结果把传闻、转载和官方公告混在一起，正文却写成确定事实；
- 长任务在并行检索、写作、审核和交付之间断链，出了问题无法恢复；
- 每次人工修改标题、语气和选题都没有沉淀，下一次还要从零开始。

NewsClaw 针对这三类问题分别用事件证据域、持久化 Team Run、Memory 与
Skill proposal 治理来处理。它不以“回答得像不像”为完成标准，而以事件、
证据、运行、审批和交付物是否能互相追溯为完成标准。

## 当前主线

### 1. 官方来源优先的事件核验

每个候选事件都带 canonical URL/hash、来源等级、claim、引用片段、发布时间、
置信度和冲突信息。缺少有效证据或存在未解决冲突，事件不能进入对外交付。
完整证据归档到 Wiki；新闻正文不会被塞进长期 Memory。

### 2. Team Run 控制面

一条确认选题创建一个 `runId`，热点发现、事实核查、内容编辑、视觉编辑与合规
交付成为带依赖的任务 DAG。任务支持并行、条件抢占、lease、heartbeat、retry、
cancel、stale recovery 和 SSE 投影，因此长任务可观察、可恢复。

### 3. 受控的运营反馈

飞书使用长连接接收运营指令、显示阶段进度并推送每日雷达；小红书生成经过证据和
合规边界检查的预览及 ZIP 素材包。对外发布前仍由人工确认。

长期 Memory 只存稳定偏好、编辑约束与反馈；Reflection/Routine Mining 默认关闭，
即使开启也只生成待审 Skill proposal，不会直接改生产能力。

## 明确边界

- 每日雷达在 `08:00 Asia/Shanghai` 发现候选并通知，不定时自动发布。
- 小红书当前是 3-18 张卡片的预览和 ZIP 素材交付，人工在创作中心上传发布。
- 微信公众号不是默认交付路径；历史草稿工具仅在显式配置凭证时使用。
- 离线评测验证策略与回归，不能虚构成线上准确率、真实投递率或模型质量指标。
